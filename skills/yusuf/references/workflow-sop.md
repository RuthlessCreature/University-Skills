# 本地科研工作流操作规程

适用于 Grant、Paper、Patent、Figure。研究者提供材料，模型负责整理与起草，本地工具负责读取、计算、制图和导出。每份结论都要能回到原文件。未完成的实验、未检出的文献和未确认的发明人信息保持空缺。

## 开始之前

1. 为本次任务建立新目录，包含 `input/`、`work/`、`output/`、`evidence/`。原件只读，工作副本保留原文件名与 SHA256。登记材料是否允许发送给当前模型服务。
2. 选定任务种类和具体模板。记录模板发布机构、年份、下载页、下载时间和文件 hash。学校模板、期刊模板、课程自制模板分别标注。打开原文，核对标题及填写说明；不能只凭文件名判断。
3. 运行器报告模型名称、服务商、支持的工具、文件访问范围和当前是否具备联网能力。只有 HTTP 响应成功不能证明工具调用可用。用一次文件读取、一次受限目录文件写入及一次计算检验能力，保留实际日志。
4. 读取本任务相关 SKILL.md。每次只执行当前节点，把下一节点需要的事实、文件路径和缺口写入检查点。不要依赖模型记住整段聊天。

## 每个节点共同遵守的约定

节点输入包括任务编号、输入文件及 hash、当前要求、允许的工具和上一节点检查结果。节点输出包括产物路径、实际调用的工具、事实来源、未决问题和状态。

状态只用 `READY`、`RUNNING`、`NEEDS_INPUT`、`FAILED`、`DRAFT_READY`。`DRAFT_READY` 表示草稿可供研究者检查，不代表科研结论成立或已获签核。模型写“已完成”不能直接改变状态；运行器必须检查文件存在、格式可读和本节点验收条件。

网络临时错误最多重试两次，记录错误码；仍失败则保存失败检查点。材料缺失进入 `NEEDS_INPUT`，先完成不依赖缺失材料的部分。恢复时核对输入 hash：输入改变则重跑受影响节点。每次修订建立新版本，保存原始失败响应，不把失败日志替换成成功日志。节点之间自动推进；正式投稿、提交申请、签名、付费或公开发布另需明确授权。

## Grant 申报书

| 步骤 | 读取什么 | 具体动作 | 留下什么 | 通过条件 |
| --- | --- | --- | --- | --- |
| G1 材料登记 | 指南、模板、申请人已确认材料 | 区分指南要求、团队事实、研究设想；逐文件登记 | intake.json、缺失清单 | 模板年度和项目类别明确；未公开资料发送范围明确 |
| G2 模板拆解 | 原始模板的每个标题和说明 | 提取章节、字数或页数限制、禁止删除的标题；保留原顺序 | template-map.json | 章节逐一对应原模板页段；不套用其他项目的结构 |
| G3 要求映射 | 指南原文、研究设想 | 每条要求对应章节和已有材料；把拟开展工作与已有成果分开 | requirements.json、outline.md | 所有硬性要求有落点；缺材料有问题编号 |
| G4 内容与路线 | 已核实事实、拟定问题 | 按问题、目标、研究内容、方法、判断标准展开；画可编辑路线图 | draft.md、route.mmd、claims.json | 每项任务对应目标与检查方式；研究假说不写成结果 |
| G5 依据核验 | 引文原文和团队证明材料 | 对重要论断摘录原句并记录页段；核对 DOI 元数据与原文适用范围 | evidence-ledger.json、issues.json | 没有虚构参考文献；查不到的依据降为待核实 |
| G6 表达与导出 | 草稿、原始模板、问题清单 | 修订空话，保留数字和限定；填入模板副本；渲染 Word 逐页检查 | grant-draft.docx、QA、运行日志 | 标题和表格结构保留；缺口可见；没有假装签核 |

先检查指南与模板，再写正文。若只给研究题目，完成 G1 的缺口清单和可讨论提纲即可；不得填造团队论文、前期实验或经费测算。2026 年面上与青年 C 的提纲不能直接推广到其他类别。高校转载模板要标明转载来源；正式提交前仍核对申报系统中的当年文件。

## Paper 论文

| 步骤 | 具体动作 | 产物与通过条件 |
| --- | --- | --- |
| P1 确认稿件类型 | 读取目标期刊指南、模板、研究问题、数据及分析记录 | journal-requirements.json；目标期刊和文章类型明确，课程二次分析注明身份 |
| P2 重建证据 | 从原数据重新计算核心统计量，核对分母、单位、缺失值与排除规则 | analysis.py、statistics.json、输入 hash；运行成功且与正文数字一致 |
| P3 写方法和结果 | 先写实际执行的方法，再写数据支持的结果 | methods-results.md；每项数值能定位计算输出，相关性不写因果 |
| P4 写引言和讨论 | 阅读检索到的原文，归纳已有认识、差异和限制 | draft.md、references.bib、引文页段；不能用 DOI 存在代替论断核验 |
| P5 审阅和修订 | 检查结论是否超出样本，核对伦理、作者、资金与数据声明 | review.json、revision.md；不自动填写伦理批准号或作者贡献 |
| P6 导出 | 按目标期刊模板排版，保留表格与图源，逐页渲染 | 可编辑稿件、图表、QA；未知声明标为待确认，未投稿 |

PLOS 官方提供 LaTeX 模板；课程制作的 Word 结构稿必须标为课程工作模板。目标期刊改变时重新解析指南。公开数据教学二次分析不能冒称本团队野外采样或新发表论文。

## Patent 技术交底

| 步骤 | 具体动作 | 产物与通过条件 |
| --- | --- | --- |
| T1 明确技术方案 | 读取高校交底书原件与发明人材料，记录公开日期和保密范围 | intake.json；只做内部草稿，不自行公开未申请方案 |
| T2 拆技术特征 | 写清部件、连接关系、输入输出、操作顺序、参数及替代方案 | feature-table.csv；每项特征能回到发明人材料，缺失处提问 |
| T3 检索已有技术 | 保存检索式、数据库、检索日期、实际阅读的权利要求与说明书页段 | search-log.json、prior-art.csv；检索失败保留缺口，不宣称全球查新完成 |
| T4 对照与实施例 | 逐项对照公开特征；写出可实施步骤、附图编号和效果证据 | disclosure.md、drawings.svg、comparison.csv；实验效果有实测依据，否则为待验证预期 |
| T5 模板导出与复核 | 填写交底书副本，核对图文一致性与必要参数，列发明人待确认问题 | patent-disclosure-draft.docx、QA、questions.json；未确认身份和权属不代填 |

高校交底书供发明人与代理机构沟通，不能当成国家知识产权局法定申请文件。已有公开专利只作阅读与比较对象；不能把其技术方案当成学员新发明，也不能仅凭相似度给出可授权结论。

## Figure 科研图表

先选择数据图、流程图或机制示意。三者不能共用“生成一张好看的科研图”作为要求。

| 步骤 | 具体动作 | 产物与通过条件 |
| --- | --- | --- |
| F1 图任务定义 | 说明要回答的问题、图类型、目标期刊和允许的视觉处理 | figure-spec.json；数据图必须提供原数据及单位，机制图标注已知关系与假说 |
| F2 数据与关系核对 | 数据图执行清洗和统计；流程图核对前后依赖；机制图逐条核对来源 | clean-data.csv 或 relation-ledger.json、日志；不生成或补造测量值 |
| F3 绘图 | 代码绘制可复现数据图，SVG 或 Mermaid 保存可编辑图形 | figure.svg、figure.png、plot.py 或 route.mmd；坐标、单位、样本量、误差线含义齐全 |
| F4 复算与视觉检查 | 独立复算核心数字，检查缩放后字体、图例、色彩和裁切 | statistics.json、QA；不把 SD、SE 和 CI 混用，不把示意箭头当成因果实证 |
| F5 图注和交付 | 图注说明数据来源、处理、排除规则及局限 | caption.md、来源记录、可编辑图、脚本和运行日志；生成机制示意单独标明生成属性 |

图像生成服务未接入时，返回清晰的未接入状态；可以提供机制图的可编辑结构稿，不能冒称调用了 Nano Banana 或其他图像服务。Figure 没有适用于所有期刊的统一官方模板，尺寸和导出要求取自目标期刊。

## 交接给其他模型

Skill 规定做事步骤；Runner 提供文件、计算和工具循环；Provider Adapter 负责请求和响应协议。分别记录三者版本。先测纯文本响应，再测结构化输出、真实工具调用、工具结果回传、多轮续接、超时和文件隔离。缺少某项能力时在兼容性表中标明，并由 Runner 补齐可确定的部分。

较弱模型每次只接收当前节点所需的材料、一个明确任务、输出结构和验收条件。要求列出所用事实，不要求输出隐藏推理过程。结构不合格时返回具体字段错误，允许一次修复；修复仍失败进入 FAILED。任何模型都不能修改原始证据来满足检查。

尚未真实调用的服务标为 UNTESTED；没有 Key 标为 NOT_CONFIGURED。不能把适配器单元测试写成服务已接通，也不能把 Codex 支持自定义 Provider 写成任意国内模型都已兼容。
